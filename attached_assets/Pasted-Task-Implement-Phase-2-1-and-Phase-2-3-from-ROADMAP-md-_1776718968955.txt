Task: Implement Phase 2.1 and Phase 2.3 from ROADMAP.md — Multi-currency support and region-aware date/number formats
Read ROADMAP.md for full context. Implement sections 2.1 and 2.3 together. Do NOT touch Phase 2.2 (i18n/translation) — that's a separate task.
This is an architectural change that touches every monetary display in the app. Proceed carefully.

Step 1: Build the formatting utility
Create a central module (e.g., src/utils/formatting.ts or equivalent) that exports:

formatCurrency(amount: number, currency: string, locale?: string): string — uses Intl.NumberFormat with style: 'currency'. Must handle BND, MYR, IDR at minimum. Must respect the currency's natural decimal rules (IDR uses 0 decimals, BND/MYR use 2).
formatNumber(value: number, locale?: string): string — locale-aware thousand separators.
formatDate(date: Date | string, locale?: string): string — uses DD/MM/YYYY for en-MY, en-ID, ms-MY, id-ID locales.
formatDateTime(date, locale?) and formatRelativeTime(date, locale?) for the timestamps added in Phase 1.4.

All functions must have sensible fallbacks if locale is undefined.

Step 2: Add currency to user profile

Add a currency field to the user model/profile (string, default "BND" for existing users so nothing breaks for the current user).
Add a locale field (default "en-BN" for existing users).
Write a migration or data fix that backfills these fields for any existing user records with the defaults above.


Step 3: IP-based geolocation on first login / signup

When a new user signs up OR an existing user logs in with currency still null/unset, call https://ipapi.co/json/ (no auth required) to detect their country.
Map country to currency + locale:

BN → BND / en-BN
MY → MYR / en-MY (we'll add ms-MY after Phase 2.2)
ID → IDR / id-ID
Any other country → USD / en-US as safe fallback


Fallback chain if IP lookup fails: use navigator.language to guess locale, map to nearest supported currency, then fallback to USD/en-US.
Never block app load on this call — if it takes >2 seconds or errors, proceed with fallback.
Cache the result so we don't re-call on every page load.

Changes save immediately and the UI updates without requiring a page reload.
