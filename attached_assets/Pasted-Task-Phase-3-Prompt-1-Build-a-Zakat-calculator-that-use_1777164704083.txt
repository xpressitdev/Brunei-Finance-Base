Task: Phase 3 Prompt 1 — Build a Zakat calculator that uses the user's account balances to compute Zakatable wealth and Zakat owed
This is the first feature in Phase 3 — the differentiators phase. Zakat is religious obligation for Muslims (~63% of Malaysia, ~87% of Indonesia, majority of Brunei). No Western finance app addresses Zakat properly. This becomes one of DuitPlan's strongest moats.
Read these files first to understand existing conventions:

src/config/regions.ts (region structure, currency, locale)
src/utils/formatting.ts (formatCurrency, formatNumber)
src/i18n/locales/en.json, ms.json, id.json (existing keys, terminology)
src/components/layout/Sidebar.tsx (nav structure)
The Goals page (src/pages/Goals.tsx or similar) for goal-creation patterns
The Net Worth page for account-balance aggregation patterns


What we're building
A new "Zakat" page accessible from the sidebar. The page lets the user calculate Zakat owed based on their existing account balances, with a clear breakdown and the option to create a Zakat savings goal.
Page sections (top to bottom):

Header — "Zakat Calculator" with a brief subtitle explaining what Zakat is in plain language
Zakatable wealth — list of all user accounts with toggleable checkboxes
Nisab threshold — input field with helper text showing approximate gold/silver values
Calculation result — clear breakdown of: total wealth, deselected, Zakatable, ≥ nisab?, Zakat owed
Action buttons — "Create Zakat goal" (creates a new Goal) + "Visit [regional body]" (external link)
Disclaimer — religious disclaimer with Shafi'i note

Note: do NOT include debt accounts in this list. Only positive-balance asset accounts (current accounts, savings accounts, etc.). If your account model has a type field, filter to asset types only.
Section 2.3: Nisab Threshold Input
Label: t('zakat.nisab.label') = "Nisab threshold"
Helper text below input:
  t('zakat.nisab.helperText') = "The minimum wealth threshold above which Zakat becomes obligatory. Traditionally calculated as the value of 85g of gold or 595g of silver."
Info icon (ℹ️) opens a popover/tooltip with reference values:
  t('zakat.nisab.referenceTitle') = "Approximate nisab values (April 2026)"
  t('zakat.nisab.referenceBody') with regional defaults:
    BN: "Gold-based: BND 16,575 (85g × ~BND 195/g)\nSilver-based: BND 1,500 (595g × ~BND 2.50/g)"
    MY: "Gold-based: MYR 54,400 (85g × ~MYR 640/g)\nSilver-based: MYR 4,800 (595g × ~MYR 8/g)"
    ID: "Gold-based: IDR 225,250,000 (85g × ~IDR 2,650,000/g)\nSilver-based: IDR 21,000,000 (595g × ~IDR 35,000/g)"
  t('zakat.nisab.referenceFooter') = "Verify current values with [regional body]. These are reference figures only — your local Zakat authority is the source of truth."
Input: numeric, currency-formatted, defaults to the gold-based nisab for the user's region (so users have a sensible starting point but can override).
Note for the agent: the reference values above (~BND 195/g, ~MYR 640/g, ~IDR 2,650,000/g for gold; ~BND 2.50/g, ~MYR 8/g, ~IDR 35,000/g for silver) are reference numbers for April 2026. Hardcode them in a constants file (e.g., src/config/zakatNisab.ts) so they can be updated easily. Add a lastUpdated field to the constants and surface it in the UI ("Reference values last updated: April 2026").

Step 3: Backend — Zakat goal creation endpoint
If the existing Goals API has a generic "create goal" endpoint, reuse it. No new endpoint needed.
If not, create a thin wrapper:

POST /api/zakat/create-goal
Body: { amount, year }
Creates a goal in the user's account with name = "Zakat ${year}", targetAmount = amount, category = "zakat" (add to category enum if needed)
Returns the created goal

No new database tables needed. Zakat is calculated on-the-fly from accounts; no need to persist Zakat-specific data.

STRICT scope boundaries — do NOT do any of the following:

Do NOT integrate with a gold price API (we're using hardcoded references)
Do NOT add madhab selection or per-madhab calculation differences (Shafi'i hardcoded for v1)

Do NOT include debt amounts as deductions from Zakatable wealth (madhab-dependent — keep simple for v1)

Do NOT modify the existing accounts schema or Goals schema (reuse existing endpoints)
