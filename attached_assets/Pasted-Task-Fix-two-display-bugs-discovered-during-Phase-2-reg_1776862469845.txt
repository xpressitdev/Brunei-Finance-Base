Task: Fix two display bugs discovered during Phase 2 region testing

Bug 1: IDR showing trailing ,00 decimals
The Indonesian region is displaying amounts as Rp 12.000.000,00 — the thousand separators (dots) and decimal separator (comma) are correct for Indonesian locale, but IDR is a zero-decimal currency and should not show the ,00 at the end.
Expected: Rp 12.000.000
Actual: Rp 12.000.000,00
Confirmed working correctly:

MYR displays as RM 7,500.00 (comma thousand separator, 2 decimals) ✓
BND displays as BND 5,769.36 (comma thousand separator, 2 decimals) ✓

So the bug is isolated to IDR only. The root cause is likely that formatCurrency is passing explicit minimumFractionDigits: 2 or maximumFractionDigits: 2 options that override the currency's native decimal settings. When Intl.NumberFormat is used with style: 'currency', the currency code itself should determine decimal places (IDR = 0, BND/MYR = 2).
Fix:

In src/utils/formatting.ts, remove any hardcoded minimumFractionDigits or maximumFractionDigits options from formatCurrency. Let Intl.NumberFormat derive decimals from the currency code.
Do not add currency-specific conditionals either — the fix is to trust the Intl API, not to special-case IDR.
Update/add unit tests:

formatCurrency(75000000, 'IDR', 'id-ID') should return "Rp 75.000.000" (no trailing ,00).
formatCurrency(5769.36, 'MYR', 'ms-MY') should return a string containing "7,500.00"-style formatting (2 decimals preserved — this is already working, just regression-guard it).
formatCurrency(5769.36, 'BND', 'en-BN') should return a string ending in .36 (2 decimals preserved — regression guard).
