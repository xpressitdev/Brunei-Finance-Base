# DuitPlan — Improvement Roadmap

## Context
DuitPlan is a personal finance tracking app (similar to YNAB) currently serving a single user in Brunei (BND currency). We're preparing to commercialize it for the **Malaysia and Indonesia markets**. This document outlines prioritized improvements across bug fixes, localization, and feature additions.

**Current stack:** Replit-hosted web app. Features include Expense Tracker, Dashboard, Accounts, Transactions, Budgets (Cash Flow Plan), Commitments, Debts, Goals, Net Worth, Upload/Import, Insights, Achievements, AI assistant (DuitPlan AI), Settings.

**Target users:** Middle-income earners in Malaysia and Indonesia, with a likely skew toward Muslim users (relevant for Zakat features).

**Deployment strategy:** One codebase, deployed to multiple regional subdomains under `duitplan.com`:
- `duitplan.com` → Brunei (default)
- `my.duitplan.com` → Malaysia (future)
- `id.duitplan.com` → Indonesia (future)

Region is detected from the hostname at app boot. Users are permanently tagged with a region at signup — no currency switching, no FX conversion, no per-account currency (deferred until there's evidence of demand). Each region gets a locale-appropriate experience without forking the codebase.

## 🌏 Phase 2 — Localization Foundation (REVISED — In Progress)

*Estimated time: 1–2 weeks, broken into 5 small nightly prompts.*

### Architectural decision
Original Phase 2 proposed a user-facing currency switcher with IP geolocation. That approach was attempted and reverted — it created confusion (e.g., switching currency just relabeled BND 5,769 as MYR 5,769 without conversion). Building a proper FX-based switcher was out of scope for current user base size.

**New approach:** Region is determined by the subdomain, not the user. No switcher. Simpler to build, simpler to explain, and naturally extensible later if we need per-account currency.

### 2.1 — Region config + formatter utilities (Prompt 1)
- Create `src/config/regions.ts` with REGIONS map (BN, MY, ID).
- Build `src/utils/formatting.ts` with `formatCurrency`, `formatNumber`, `formatDate`, `formatDateTime`, `formatRelativeTime`.
- Add `region`, `currency`, `locale`, `language` fields to user model (defaults: BN).
- Write unit tests for formatters including IDR zero-decimal and NaN sanitization.
- **No UI changes.**

### 2.2 — Hostname-based region detection (Prompt 2)
- At app boot, read `window.location.hostname` and map to region.
- `duitplan.com` → BN, `my.duitplan.com` → MY, `id.duitplan.com` → ID.
- Unknown hostnames (localhost, preview URLs) → fall back to BN with env variable override support.
- Expose region via React context / app-level state so all components can access it.
- New user signups auto-inherit the current region.

### 2.3 — Refactor monetary displays to use the formatter (Prompt 3)
- Audit every page: Dashboard, Expense Tracker, Accounts, Transactions, Budgets, Commitments, Debts, Goals, Net Worth, Upload, Insights, Premium, AI chat responses.
- Replace hardcoded BND strings, `.toFixed(2)` calls, and custom currency logic with `formatCurrency(amount, user.currency, user.locale)`.
- Split into two sub-prompts if needed (first half: core pages; second half: secondary pages).
- **Acceptance:** manually setting a test user's currency to MYR or IDR renders every page correctly.

### 2.4 — Refactor date displays (Prompt 4)
- Replace all `toLocaleDateString()` and raw date formatting with `formatDate(date, user.locale)`.
- Dates should render as DD/MM/YYYY across all target locales.
- Use `formatRelativeTime` for "last updated" timestamps from Phase 1.4.

### 2.5 — i18n infrastructure + English extraction (Prompt 5)
- Install and configure `i18next` + `react-i18next`.
- Create `src/locales/en.json`, `src/locales/ms.json`, `src/locales/id.json` (latter two empty stubs for now).
- Extract all UI strings from every page into `en.json` using structured keys (e.g., `nav.dashboard`, `insights.spendingTrend.title`).
- Wire up language detection to read from `user.language`.
- **No translations yet** — those are a separate content task (Phase 2.6).

### 2.6 — Malay and Indonesian translations (content task, can be parallelized)
- Translate `en.json` into `ms.json` and `id.json`.
- Do NOT auto-translate one from the other — they have different finance vocabulary (e.g., Account: *Akaun* in MY, *Rekening* in ID).
- Flag low-confidence terms for native-speaker review before shipping.

### What's explicitly NOT in Phase 2
- User-facing currency switcher
- IP geolocation service
- FX rate lookups or conversion
- Per-account currency support
- Historical FX rate storage

These are deferred until there's user demand (likely a future Phase 5 or Phase 6). Phase 2 as scoped is sufficient for launching a clean regional experience on each subdomain.

## 🕌 Phase 3 — Market Differentiators
*Estimated time: 2–3 weeks. These make you stand out vs. YNAB/Mint/Monzo.*

### 3.1 Zakat Calculator
**Why:** Malaysia (~63% Muslim) and Indonesia (~87% Muslim) — no Western finance app addresses this. Huge differentiator.
**Acceptance criteria:**
- New section under Goals or as a standalone tool: "Zakat Calculator".
- Calculate Zakat on savings (2.5% if balance > nisab threshold for 1 hijri year).
- Pull nisab threshold dynamically (gold price-based) or allow manual entry.
- Show current nisab status based on user's account balances.
- Option to create a Zakat payment goal automatically.
- Region-aware: surface the relevant Zakat body per region (MUIB in BN, LZS in MY, BAZNAS in ID).
- Optional: notify user when their savings have held above nisab for 1 year.

### 3.2 Local bank statement import
**Why:** The more banks you parse automatically, the stickier the product.
**Priority banks:**
- **Brunei:** BIBD, Baiduri, Standard Chartered Brunei.
- **Malaysia:** Maybank, CIMB, Public Bank, RHB, Hong Leong, Bank Islam.
- **Indonesia:** BCA, Mandiri, BNI, BRI, Bank Syariah Indonesia (BSI).
- **E-wallets:** GrabPay, Touch 'n Go, Boost (MY); GoPay, OVO, DANA (ID).

**Acceptance criteria:**
- Each supported bank has a named parser that handles PDF statements and CSV exports.
- AI fallback for unsupported formats (already built — retain it).
- Show "Supported banks" list clearly on the Upload page, filtered to the user's region.

### 3.3 Shared household budgets (stretch)
**Why:** SEA finance is often managed household-wide. YNAB does this poorly.
**Acceptance criteria:**
- Invite a spouse/family member to view-only or co-manage budget.
- Transactions tagged by household member.

## 💰 Phase 4 — Monetization & Growth
*Estimated time: 1–2 weeks. Do once product is rock solid.*

### 4.1 Local payment methods for subscription
**Acceptance criteria:**
- **Malaysia:** Integrate Billplz or iPay88 for FPX (online banking), GrabPay, Boost, TNG eWallet.
- **Indonesia:** Integrate Xendit or Midtrans for GoPay, OVO, DANA, BCA VA, QRIS.
- Keep Pocket Pay for Brunei.
- Payment methods shown based on user's region.

### 4.2 Regional pricing
**Acceptance criteria:**
- Tiered regional pricing:
  - Brunei: BND 10/month (current)
  - Malaysia: MYR 15–19/month
  - Indonesia: IDR 39,000–49,000/month
- Show annual pricing with ~20% discount.
- Prices display in the user's regional currency on the Premium page (no FX, hardcoded tier per region).

### 4.3 Free tier for funnel
**Acceptance criteria:**
- Free tier: up to 50 transactions/month, 1 account, basic dashboard. No AI, no debt simulator, no insights.
- Premium: unlimited + all features.
- Clear upgrade prompts when hitting limits (non-annoying).

### 4.4 Referral program
- 1 free month for each successful paid referral (both referrer and referee).
- Simple shareable link.
